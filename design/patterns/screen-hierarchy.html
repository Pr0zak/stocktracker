Screen hierarchy

Hierarchy is earned by importance, not by what was built most recently. Both main screens had drifted the other way — the Watchlist opened with four context cards before a single holding, and Portfolio put a cash-entry form between the chart and the positions. The lower half of this sheet is proposals with nothing built behind them.

Open proposals

nothing built

Ideas worth arguing about on this canvas before any of them becomes Kotlin. Each one trades something real away; none is obviously correct.

  1. Sticky value header watchlist

    A one-line portfolio total that pins to the top once the list scrolls. A full value card was tried at the top of the Watchlist and removed — it pushed the list down as badly as the context cards had. Sticky gets the number without paying for it twice. Cost: a second persistent bar under the app bar, on a screen that already has filter chips.

  2. Sector grouping in the list watchlist

    The heat map already groups by sector and the classification is cached server-side, so the data is free. Collapsible sector headers would make a twenty-name list scannable by theme rather than by memorised order. Cost: it fights manual drag-reorder, which is the current organising principle and which people use deliberately.

  3. Swipe-right to open detail rows

    Swipe-left already deletes. The opposite gesture is unused and detail is the most common destination. Cost: gesture collision with the reorder drag, and swipe affordances are invisible until discovered.

  4. Density as a setting rows

    Comfortable / compact, the way mail clients do it. The tighter row shipped as the only option; someone who reads company names rather than tickers lost something. Cost: another switch in a Settings screen that already has many, to serve a preference nobody has asked for yet.

  5. Inline expansion instead of navigation rows

    Tapping a row expands it in place — chart, signal, key levels — rather than pushing a screen. Keeps you in the list while comparing names, which is the actual task. Cost: the detail screen is rich enough that a useful inline version is most of a rewrite, and it would fork two presentations of the same content.

The test used throughout. Would someone glancing at this screen for two seconds, one-handed, on a bus, get what they came for? That question demoted every context card on the Watchlist and moved the cash form on Portfolio, and it is the one to apply to the proposals above. Note on the removed value card: it was built, shipped in v0.81.0 and taken out a day later. The number was right and the placement was wrong — it reclaimed the space the collapsed context cards had just freed. That is the argument for the sticky variant rather than against showing the total at all.
